# Secret scanning

`TruffleHog secret scan` is the PR head/prospective-merge result. Repository push and history scans use a separate fixed check name, so they cannot replace that result. Both scans block every unsuppressed detection. Provider verification is disabled: CI does not contact live services using candidate credentials. Native verified, unknown, unverified and filtered-unverified results are retained; offline nonverified results are reported as unverified.

The scanner release and download checksum are immutable. All trusted scans load policy from the accepted default branch. PR targets are restricted to the owning integration and default branches; auxiliary bases never supply executable policy. Manual qualification must dispatch the default-branch workflow with a PR number, never dispatch a candidate branch. Trusted scans parse the candidate exception file as an inert Git blob with the accepted parser and record validation; candidate rules never suppress their own scan. The unprivileged PR job also validates policy before its regression tests. Ordinary PR regression tests have no write token. The privileged job has only repository read and check-write permissions; the scanner subprocess receives no GitHub or provider credentials.

The gate waits within a bounded readiness window, then enumerates every introduced commit from the merge base and validates the prospective merge against the authenticated current head and base branch tip. Privileged runs remain uncancelled until their check lifecycle can finish; only unprivileged candidate regressions are cancelled by newer PR events. It scans complete added, modified and type-changed blobs, including novel merge resolutions, changed renames and symlink targets. Unchanged content inherited from any merge parent retains its original association. Nonforward branch updates, including updates whose former tip is no longer locally available, scan complete reachable new-head history. PR ranges still require their base object. Branch deletion scans the retained former tip or refuses before creating an unrelated default-head check. Detection deduplication is disabled so identical values in distinct blobs each receive their own disposition. Generated regular files keep candidate paths and symlinks inert. Commit metadata and changed filenames are scanned separately. A deleted secret remains covered by its introducing commit. Scheduled scans cover the full reachable default-branch commit history and current annotated tag objects. Every branch push is covered; tag pushes trigger full scans; removed tag objects that are no longer available are outside a later repository snapshot. Every tag and its referenced Git content must remain inert; each submodule repository owns its own Git content scan. External Git LFS object contents are outside the stored Git object scope.

Scanner reports and retained artifacts expose only detector, immutable Git object identity, path digest, line, source kind and disposition. They never publish raw findings, filenames, email or scanner diagnostics. Surrounding CI logs are not globally certified as redacted: the pinned checkout action can print a candidate commit subject. Avoid placing credentials in Git metadata; scanning metadata does not erase an earlier checkout log. Missing objects, incomplete output, warnings/errors, malformed diagnostics, timeout or resource limits refuse a pass. Bounds are 256 MiB per stored object, 8 GiB unique object data, one million source associations, 256 MiB scanner stdout and 16 MiB scanner stderr. Output bounds apply while the child runs, with process-group cleanup on timeout or refusal. Exceeding a bound requires qualification of a larger bounded scan, never an automatic clean verdict.

`exceptions.json` is empty by default. A source-proven false-positive exception needs repository, detector, exact path, immutable commit, SHA256 of the detector's raw value, Daniel's ownership, a `proof` URL identifying that exact repository/commit/path on GitHub, rationale and expiry. Verified findings, commit metadata, tag metadata and filename detections cannot be excepted. Exceptions do not propagate: an unrelated later edit to a file containing a fixture requires a separately reviewed commit-specific exception. Never waive an entire directory, detector or value across commits. Expired exceptions block again.

Before approving an exception, inspect its immutable source in a private review, prove the matched value is a synthetic fixture or program/interface identifier, and verify no live credential is involved. For a real credential, rotate it and handle historical exposure; deleting its latest source does not clear history.

Run `TRUFFLEHOG_BINARY=/absolute/path/to/checksum-verified/trufflehog python3 .forlex/security/test_secret_scan.py` to qualify both protocol tests and real offline canaries. Omitting the binary skips native qualification and is insufficient for rollout.

Activation remains held: GitHub Actions app identity and a check name alone do not distinguish a trusted scanner from a candidate workflow. A separately accepted and qualified issuer or immutable required workflow is necessary before this scan can replace GitGuardian. Accept the owning source PR, publish accepted source to the default branch where required, qualify every current head/base/prospective-merge context, then enable the separately trusted required gate before removing GitGuardian. Requalify expired exception and changed-source contexts; preserve other branch rules. A repository with Actions disabled is not covered until its scanner workflow is explicitly enabled. Initial API verification failures, partial completion and local context persistence failures attempt fresh, independent cleanup of each known original check; unknown or foreign identities are never guessed or changed. Only redacted result artifacts are retained, for 14 days.
